# cloud/ — рендер урока в облаке и проверка сцен

Здесь всё, что считает тяжёлое **не на ноутбуке**: параллельный рендер 2K-ролика на Hugging Face Jobs (основной путь), запасной путь на Modal и облачная проверка отдельной сцены кадрами каждые 0,5 с.

| Файл | Что делает |
|---|---|
| `hf_render.py` | **основной рендер**: бандл → датасет → 72 задачи → склейка `-c copy` → звук → проверка мастера |
| `scene_check_hf.py`, `scene_check_hf_worker.py` | проверка одной сцены в облаке: листы кадров каждые 0,5 с + стиллы |
| `modal_render.py` | **запасной** рендер на Modal |
| `worker/` | образ воркера (Dockerfile, `render_chunk.py`) и `setup_hf.py` — разовая настройка Hugging Face ([`worker/README.md`](worker/README.md)) |
| `lib/orchestrator.py`, `lib/bundle_isolated.py` | движок: бюджет, ledger, повторы, отмена; изолированный бандл |
| `requirements.txt` | `huggingface_hub`, `pyyaml` (+ `modal` для запасного пути) |

## Где считать: выбор
Правило: **есть Hugging Face PRO → рендерим на Hugging Face; нет → Modal; нет ничего → локально.**

| Путь | Скорость и цена (замеры автора, 14-минутный 2K-урок) | Условия |
|---|---|---|
| **Hugging Face Jobs** (основной) | **≈ $0.13**, **3,5–5 минут** при 72 воркерах `cpu-upgrade` (самый медленный замер — 5,6 мин) | PRO — $9/мес («8× ZeroGPU quota», «$2 of included inference credits monthly»); железо «CPU Upgrade: $0.03 per hour (8 vCPU, 32 GB)» — это цена задачи за час, минимум минута на задачу |
| **Modal** (запасной) | быстрее — **≈ 2–3 минуты**, но дороже — **≈ $1 за урок** | Starter — $0 + расход, «$30 in monthly free credits» |
| **Локально** (последний вариант) | `npx remotion render` — **≈ 1–1,5 часа** на 8 ядрах; 3-минутный ролик — 15–20 минут (оценка из `skills/cloud-render/SKILL.md`, проверить на своей машине) | ничего, кроме ноутбука |

Почему Hugging Face основной: по замерам автора ≈ $0.13 против ≈ $0.92 у Modal за тот же урок (примерно в 7 раз дешевле) при разнице по времени в пару минут; Modal удобен, когда нужен самый быстрый результат или нет PRO. Все цифры скорости и цены — **из замеров автора**, а не гарантии: реальный расход покажет ledger запуска и биллинг площадки.

**Карты.** Обе площадки просят привязать карту (при нулевом использовании ничего не списывают). Hugging Face принимает обычные карты. На Modal, по опыту учеников автора, виртуальные и предоплаченные карты принимаются не всегда — пробуйте разные (это опыт учеников, а не правило площадки).

## Порядок для Hugging Face (один раз и на каждый рендер)
Все команды ниже запускайте **из корня набора** (пути `remotion`, `public/lesson1/voice.wav` и `out/…` в примерах считаются от него; `--audio` дополнительно ищется от папки проекта).

1. **Токены.** Токен HF с правом write → в `.env` как `HF_TOKEN` (никогда не печатать и не коммитить). `pip install -r cloud/requirements.txt`; в `remotion/` — `npm install`.
2. **Space + датасет (один раз):** `python3 cloud/worker/setup_hf.py --project remotion` — создаст приватные `video-render-assets` и `remotion-speed-worker`, соберёт образ. Подробно и вручную — [`worker/README.md`](worker/README.md). В конце выведет две строки для `.env`: `HF_DATASET=…` и `HF_WORKER_IMAGE=…`.
3. **План (бесплатно, облако не вызывается):**
   ```bash
   python3 cloud/hf_render.py --project remotion --lesson 1 --comp Lesson1 \
     --audio public/lesson1/voice.wav --workers 72 --out out/lesson1_2k.mp4 --budget 0.50 --dry-run
   ```
   Печатает: число кадров, нарезку на куски, таймаут, пиковый резерв бюджета, оценку цены и список проблем (✗ — остановят боевой запуск, ⚠ — предупреждения). **Агенту: показать человеку этот вывод и дождаться «ок» до `--live`.**
4. **Боевой запуск:** то же самое с `--live`. Что происходит: считается число кадров → собирается изолированный бандл (только нужный урок, 45–55 МБ по замерам автора) → выгружается в датасет → запускаются задачи → куски скачиваются, склеиваются `ffmpeg -c copy` → накладывается голос со сдвигом 500 мс (голос начинается с кадра 15) → проверка мастера (число кадров, кодеки).
5. **Дальше:** `bash scripts/finish.sh out/lesson1_2k.mp4 out/lesson1_final_2k.mp4` (громкость −14 LUFS, превью) и листы кадров вокруг мест с лицом (`scripts/frames_05s.py`).

### Флаги `hf_render.py`
| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--project` | `KIT_ROOT/remotion` | проект Remotion |
| `--lesson N`, `--comp` | —, `LessonN` | урок и композиция |
| `--audio` | `public/lessonN/voice.wav` проекта | голос; путь ищется как есть, затем от проекта, затем от `KIT_ROOT` |
| `--workers` | 72 | число параллельных задач (нарезка `fixed-chunks`: поровну) |
| `--out` | `KIT_ROOT/out/lessonN_2k.mp4` | итоговый файл; относительный путь — от текущей папки |
| `--budget` | 0.50 | программный предохранитель, $ |
| `--live` / `--dry-run` | dry-run | без `--live` ничего не запускается |
| `--frames` | из `public/lessonN/timeline.json` | `ceil((duration + 15/30 + 3) × 30)` — как `lessonFrames()` в `theme.ts`; после сборки бандла число сверяется с композицией (`remotion compositions`) |
| `--audio-offset-ms` | 500 | сдвиг голоса (LEAD = 15 кадров при 30 fps) |
| `--dataset`, `--image` | `HF_DATASET`, `HF_WORKER_IMAGE` | датасет и образ воркера |
| `--job-timeout` | подбирается по размеру куска | таймаут задачи, с |
| `--resume LEDGER` | — | доделать прерванный запуск (нужен `--live`) |
| `--skip-bundle` | — | не пересобирать бандл, взять уже выгруженный |
| `--cleanup-remote` | — | после успеха удалить куски `renders/<run_id>` из датасета |
| `--work` | `KIT_ROOT/work/hf_render` | рабочая папка: бандл, `runs/<run_id>/` (ledger, куски), записанный `lessonN_config.yaml` |

Масштаб ровно `1.3333333333333333` (1920×1080 → 2560×1440); `1.3333` даёт нецелую высоту и падение.

### Бюджет и безопасность
- **Это программный предохранитель оркестратора, а не лимит биллинга Hugging Face** — жёсткий лимит расходов ставится в настройках биллинга площадки. Перед запуском каждой задачи резервируется «таймаут × $0.0005/мин»; если пик резервов (задачи × резерв) больше `--budget`, `hf_render.py` откажется стартовать и скажет, что поднять. Таймаут по умолчанию подбирается по размеру куска (консервативно: 1,5 кадра/с + 180 с на скачивание, распаковку и запуск Chromium; у автора воркеры давали 1,94–5,69 кадра/с).
- Каждая задача тарифицируется поминутно, минимум минута; упавшая попытка тоже стоит денег и учитывается.
- Задачи запускаются только через `--live`. Ни конфиг, ни `--resume` сами по себе платный запуск не разрешают.
- Неясный исход (оборвалась связь при опросе задачи) → кусок помечается `OUTCOME_UNKNOWN`, второй платный запуск **не** делается, пока человек не разберётся.

### Обрыв, отмена, возобновление
```bash
python3 cloud/lib/orchestrator.py status --ledger work/hf_render/runs/<run_id>/ledger.json   # сколько кусков готово, расход
python3 cloud/lib/orchestrator.py cancel --ledger work/hf_render/runs/<run_id>/ledger.json   # остановить задачи в облаке
python3 cloud/hf_render.py <те же аргументы> --resume work/hf_render/runs/<run_id>/ledger.json --live   # доделать недостающее
```
Ctrl+C во время запуска тоже отменяет задачи в облаке (путь к ledger печатается в начале). Готовые куски проверяются `ffprobe` и не рендерятся повторно. Куски остаются в `work/hf_render/runs/<run_id>/chunks/` и в датасете `renders/<run_id>/` (`--cleanup-remote` удаляет их из датасета; освобождается ли при этом место в квоте датасета — **проверить**).

### Если что-то пошло не так
| Сообщение | Что делать |
|---|---|
| `нет ключа HF_TOKEN` | задать `HF_TOKEN` (токен с правом write) или войти командой `hf auth login` (в старых версиях — `huggingface-cli login`) |
| `не задан датасет` / `не задан образ воркера` | `python3 cloud/worker/setup_hf.py …`, затем переменные `HF_DATASET`, `HF_WORKER_IMAGE` |
| `в … нет node_modules` | `cd remotion && npm install` |
| `нет файла голоса` | `voice.wav` урока (`scripts/tts_timeline.py`) в `public/lessonN/` или флаг `--audio` |
| `бюджет … меньше пикового резерва` | поднять `--budget` или уменьшить `--workers` / `--job-timeout` |
| `Бандл … МБ больше порога` | в `public/lessonN/` лежит лишнее (черновики видео); убрать или `--max-bundle-mb` |
| сборка бандла упала | `cd remotion && npx tsc --noEmit` и `npx remotion compositions src/index.ts` — ошибка в коде сцен |
| `в композиции N кадров, а --frames M` | убрать `--frames` (число берётся из композиции) или исправить |
| задача упала | в логах задачи (huggingface.co/jobs) — конец вывода Remotion; повторится автоматически до `--retries` раз |

## Проверка одной сцены в облаке
Агент проверяет сцену **кадрами каждые 0,5 с**, а не «на глаз». Код проекта (1–3 МБ) уходит в датасет, одна задача `cpu-upgrade` собирает проект и рендерит нужный отрезок в масштабе 0,5× без звука + стиллы; листы собираются локально.
```bash
# один раз и после изменения голоса / роликов лица / вырезов в public/lessonN:
python3 cloud/scene_check_hf.py --sync 1
# проверить отрезок 12–24 с голоса и два стилла (секунды голоса, как в timeline.json):
python3 cloud/scene_check_hf.py remotion 1 12 24 --stills 12,18 --tag l1_intro
# сначала можно посмотреть план — токен и облако не нужны:
python3 cloud/scene_check_hf.py remotion 1 12 24 --stills 12,18 --tag l1_intro --dry-run
```
- Результат: `work/scene-check/<tag>/sheet_01.jpg …` — листы 6×4 кадра, **каждые 0,5 с**, с подписью секунды голоса (подписи нужны системный шрифт и ffmpeg с `drawtext`; нет шрифта — листы без подписей, скрипт скажет); `still_<сек>.png` — полные кадры 1920×1080; `range.mp4`.
- Время ≈ **2–5 минут**, стоимость ≈ **$0.003** (по замерам автора: задача 3–6 минут на `cpu-upgrade`, $0.03/ч ⇒ $0.0005/мин).
- Открыть листы и сверить: элементы появляются на слове-якоре, ничего не вылезает из зоны вёрстки, нет наложений. Нашли ошибку — править сцену и повторять с тем же `--tag`.
- Несколько агентов могут проверять одновременно: коммиты в датасет повторяются при конфликте. После успеха временные файлы проверки удаляются из датасета.
- Время во всех аргументах — секунды **голоса** (голос начинается с кадра 15, то есть +0,5 с к времени видео; скрипт пересчитывает сам).

## Modal (запасной путь)
```bash
pip install modal            # один раз
modal token new              # один раз: вход в аккаунт Modal (токен хранится в ~/.modal.toml)
python3 cloud/modal_render.py --project remotion --lesson 1 --dry-run                  # план, Modal не вызывается
python3 cloud/modal_render.py --project remotion --lesson 1 --out out/lesson1_2k.mp4 --chunks 72
```
Первый запуск собирает образ Modal (несколько минут: Node 22, Chromium, шрифты, зависимости из вашего `remotion/package.json`); следующие — быстрее. Обёртка вызывает `modal run cloud/modal_render.py …`; можно и напрямую. Параметры: `--project`, `--lesson`, `--out`, `--chunks` (куски = контейнеры, по умолчанию 72), `--cpu` (ядер на контейнер, 8), `--audio`. Карты и нюансы аккаунта — см. выше. Стоимость смотрите в Modal → Usage; по замерам автора ≈ $1 за 13-минутный урок при 72×8 ядер (больше ядер на контейнер быстрее не делает: очередь контейнеров). Скрипт не проверялся на живом аккаунте Modal в этой сборке набора — первый запуск делайте на коротком уроке.

## Локальный рендер (последний вариант)
```bash
cd remotion
npx remotion render src/index.ts Lesson1 out/lesson1_2k.mp4 --scale=1.3333333333333333
```
≈ 1–1,5 часа на 8 ядрах для 14-минутного ролика (замер автора); 3-минутный — 15–20 минут (оценка из `skills/cloud-render/SKILL.md`, проверить на своей машине). Не рендерьте на ноутбуке 14-минутный ролик, если доступно облако.

## Что исправлено в движке относительно оригинала автора
`lib/orchestrator.py` — копия проверенного оркестратора автора (v2.2) с правками набора: имена датасета/образа только из настроек; воркер запускается из образа (`/app/render_chunk.py`), а не скачивается из датасета; стадия задачи читается через `JobStage.value` (иначе в Python ≥ 3.11 задача никогда не считалась завершённой); логи `fetch_job_logs` склеиваются из итератора; превышение бюджета больше не превращается в `OUTCOME_UNKNOWN`; токен — также из `huggingface-cli login`; в dry-run отсутствие токена не ошибка. Подробности — в шапке файла.

## Что не проверено
Боевой путь (`--live`, сборка Space, `modal run`) требует аккаунтов и денег и не запускался при сборке набора. Проверялось: синтаксис, `--help`, dry-run, сборка изолированного бандла на `remotion/`, разбор длительности композиции из `remotion compositions`, логика оркестратора на заглушке API Hugging Face. Первый боевой запуск — на коротком ролике, с `--budget` поменьше.
